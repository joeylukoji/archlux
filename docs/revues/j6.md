# Review of milestone 6: L rooms, active learning, IFC export

## Criterion as written

`MILESTONE-6.md` §0: "A person who has never seen the code must succeed in 10 minutes":
`pip install archlux`, copy the example of `docs/galerie/01`, run it on their own plan,
get a valid plan and a certificate. "To be checked **by a real person outside the
project**, not by an automatic test." The milestone also delivered L-shaped rooms,
active learning (with the conclusion "active loses against random") and IFC export
(survival rate 80 %).

## Replayed?

Partly, on revision `f03c23f` and later.

- **External user test: not replayed.** It needs people outside the project and a
  package on PyPI; it is phase 5 (usability), after the public release of phase 8
  starts. Until then the criterion is **not met**: nobody outside the project has run
  it.
- **L rooms**: replayed in phase 1 (batch 1.7 and its review, 2000 Hypothesis examples).
- **Active against random**: `python experiences/j6_active.py` (English, 48 lines),
  `resultats/j6_active.csv`, 30 paired campaigns.
- **IFC**: `python experiences/j6_ifc.py` (45 lines), `resultats/j6_ifc.csv`, files
  opened and validated by **ifcopenshell** 0.8 (schema and rules), and
  `tests/unites/test_ifc_validation.py`.

## Result

**Active against random.** The old comparison used `seed + cycle` for selection and
training (AUDIT.md Q-M5): the campaign of seed 17 at cycle 1 replayed the campaign of
seed 18 at cycle 0, so its 10 campaigns were not independent. `active.Loop` now draws
named sub-seeds (`archlux.seeds.derive`: `selection/k`, `fit/k`, `split`), and the
campaigns use derived seeds.

| | Published (10 correlated campaigns) | Replayed (30 paired campaigns) |
|---|--:|--:|
| mean final width, random | 14.93 | 10.96 (sd 3.66) |
| mean final width, active | 16.35 | 12.30 (sd 5.83) |
| active narrower in | 4 / 10 | 16 / 30 |
| paired test | none | Wilcoxon p = 0.53 |

**No difference is detected.** "Active loses" was not supported by the data; "active
wins" is not either. With a paired standard deviation of 6.4, 30 campaigns detect a
difference of about 3.3 (80 % power, 5 % level): smaller effects remain possible.

**IFC.** The "survival rate" of 80 % was fixed by its input (40 healthy plans and 10
pathological ones by design), and `validate=True` meant "our own pathology check
passed": **no IFC reader had opened a file**. Opened with ifcopenshell, **every
exported file was rejected**:

- GlobalIds written as 22 hexadecimal characters instead of IFC base 64 (the docstring
  said "to be replaced before any real BIM exchange");
- `IfcOwnerHistory` with `ChangeAction = ADDED` and no modification date;
- `Curve2D` footprints built from 3D points;
- openings voiding no element;
- and, found while checking positions: **every wall was drawn shifted by its first
  end** (placed at `a`, with an axis running from `a` to `b` in that frame).

All five are fixed. Replayed on 90 repaired synthetic plans: **90 / 90** files accepted
by ifcopenshell with zero error (Wilson 95 % [0.959, 1.000]); before the fix, 0 / 90.
An opening on a wall that is not in the plan is now a pathology
(`ouverture_orpheline`), refused by `validate=True`.

## Decision

- **External user criterion: kept, not met**, moved to phase 5; the README must not
  call the library usable by a third party until it is met.
- **"Active loses": withdrawn**, replaced by "no difference detected (30 campaigns,
  Wilcoxon p = 0.53)". The `seed + cycle` defect is fixed in the library.
- **IFC criterion rewritten**: an exported file must be accepted by an independent IFC
  validator (ifcopenshell, in CI through the `dev` extra); the survival rate is
  measured on repaired plans, never on a mix chosen in advance. Opening the files in a
  BIM application (Revit, Archicad, BlenderBIM) stays a phase 5 check.
- Traced in [ADR 0002](../adr/0002-milestone-criteria-rewritten.md).
